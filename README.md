## ⚡ Quick Start

```bash
# 1. Clone the repository
git clone https://github.com/<your-username>/nlp-sentiment-classifier.git
cd nlp-sentiment-classifier

# 2. Create a virtual environment (recommended)
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Download / prepare the dataset
#    Option A — Full IMDb dataset (~84 MB, requires internet)
python generate_data.py

#    Option B — Quick 5 000-review sample
python generate_data.py --sample

#    Option C — Fully offline synthetic data
python generate_data.py --synthetic

# 5. Train all models and generate plots
python classifier.py --train

# 6. Predict sentiment on custom text
python classifier.py --text "This movie was absolutely amazing!"
```

### Why TF-IDF?

**TF-IDF** (Term Frequency–Inverse Document Frequency) is a standard baseline for NLP text classification because:

1. **TF** up-weights terms that appear frequently *in a document*
2. **IDF** down-weights terms that appear in *most documents* (e.g., "the", "is")
3. **Bigrams** capture negation patterns like "not good", "wasn't great"
4. **Sublinear TF** (`1 + log(tf)`) reduces the outsized impact of very frequent terms

### Model Selection Rationale

| Model | Strengths | Weaknesses |
|-------|-----------|------------|
| **Naive Bayes** | Extremely fast, good baseline, handles sparse data well | Independence assumption, less accurate |
| **Logistic Regression** | Interpretable coefficients, calibrated probabilities | Slower on large vocab |
| **Linear SVM** | Best generalisation on text, fast at test time | No probability output by default |

## 🧠 Key Design Decisions

1. **Pipeline architecture** — Each model is wrapped in a `sklearn.Pipeline` so preprocessing and inference are atomic. This prevents data leakage and makes deployment trivial: `pipe.predict(["new text"])`.

2. **Stratified splitting** — `train_test_split(..., stratify=y)` preserves the 50/50 class balance in both splits.

3. **No stemming/lemmatisation** — Kept deliberately absent. Empirically, TF-IDF + sublinear scaling on raw tokens already performs well on movie reviews; stemming can hurt bigram quality.

4. **Model serialisation** — The best model is saved with `pickle` so inference (`--text`) requires no retraining.

5. **Modular codebase** — Every concern (loading, preprocessing, training, evaluation, visualisation, CLI) is an isolated function, making unit testing and extension straightforward.
